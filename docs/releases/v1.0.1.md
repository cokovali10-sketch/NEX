# NEX 1.0.1

This is the first NEX release with downloadable binaries. It supersedes the
`v1.0.0` tag, which was created before CI passed and was never published with
release assets.

## Why 1.0.1 exists

- The `v1.0.0` CI run failed at the formatting step, so Clippy and the test
  suite never ran for the tagged commit.
- The `v1.0.0` GitHub release had zero assets and could not be installed
  without cloning and building from source.
- `v1.0.1` is built by a release workflow that runs formatting, Clippy, and the
  full test suite on Windows and Ubuntu before it publishes anything.

## What NEX is

NEX is a statically typed, natively compiled language. The compiler lowers NEX
source through its own lexer, parser, semantic analyzer, and IR to LLVM textual
IR, then invokes Clang to produce a standalone executable. There is no
interpreter and no bytecode VM.

## Highlights

- Functions, bindings, `if`/`elif`/`else`, `while`, range `for` loops, and
  `for x in array` iteration.
- Structs (including nested and generic structs), enums with `match`, fixed and
  growable arrays, tuples, and tuple destructuring.
- Traits with static dispatch and inherent methods via `impl Type:`.
- Generic functions and structs via monomorphization; generic calls and
  constructors infer their type arguments.
- Modules, `use`, `import`, and `from ... import` file imports.
- Strings with indexing, slicing, f-string interpolation, and the string
  runtime helpers.
- Bitwise operators, octal literals, compound and parallel assignment,
  explicit casts, and `extern "C"` calls.
- Runtime-backed standard library: files, blocking TCP/HTTP helpers, JSON,
  string-keyed maps, threads/mutexes, a thread pool, a router, a string
  builder, time and math.
- CLI: `build`, `run`, `check`, `test`, `clean`, `doctor`, `fmt`, `lint`,
  `add`, `benchmark`, `debug`, `profile`, and `version`.

## Install

Download the archive for your platform and verify its SHA-256 checksum.

### Windows

Extract `nex.exe` from `nex-v1.0.1-windows-x86_64.zip`, put it on `PATH`, then:

```powershell
nex --version
nex doctor
```

### Linux

Extract the `nex` binary from `nex-v1.0.1-linux-x86_64.tar.gz`, put it on
`PATH`, then:

```bash
nex --version
nex doctor
```

The compiler binary does not need Rust at runtime. Compiling NEX programs
requires Clang in `PATH`; this release was tested with Clang 23.1.4. Run
`nex doctor` to check the toolchain and a small end-to-end compile.

## Performance notes

- Scalar integer loops compile to code at parity with equivalent Rust code.
- Vectorizable floating-point loops can be faster in Rust because LLVM
  auto-vectorizes them; NEX does not yet apply equivalent loop optimizations.
- The HTTP server example is roughly 15-20x slower than an `axum` baseline.
- NEX does not claim to be faster than Rust. See `benchmarks/README.md` for the
  measured numbers and the benchmark sources.

## Known limitations

- No ownership, borrowing, or lifetime checking; there is no garbage collector,
  so long-running programs that build many heap values can leak memory.
- No async/await or structured concurrency.
- Generic type arguments in type annotations (for example `Box<i64>`) are not
  accepted yet; generic calls and constructors infer them.
- `nex debug` and `nex profile` are build-and-run helpers, not a debugger or a
  sampling profiler.
- Windows is the primary end-to-end tested host; CI also tests Ubuntu.
  `--target` selects a Clang target, but cross-target output is not validated
  by the test suite.
